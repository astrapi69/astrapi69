# Git, pull requests, issues and releases

- Work in gitflow: branch feature/*, fix/* or chore/* from develop and open the PR against develop; main or master takes only releases and hotfixes. (AG-056)
- Create a feature branch with `git checkout --no-track -b <branch> origin/develop` and push it with `-u`; only develop may track origin/develop. (AG-057)
- Never rewrite pushed history: no force-push and no amend of a pushed commit (add a new one), not even to remove old attribution lines or old author addresses. (AG-058)
- Run `git pull --ff-only` before every merge and every push; when a push is rejected, sync onto the remote and check that your content arrived. (AG-059)
- Run the cheap checks before the commit and push it at once, subagents too (check with git ls-remote); let CI run the full suite and merge only when green. (AG-060)
- Before pushing a follow-up to a PR branch, check with `gh pr view <n> --json state` that the PR is still open; if it is merged, branch anew from develop. (AG-061)
- Never stash in commands, scripts or loops (all worktrees share the stash stack); set work aside in a WIP commit, and let a repo loop skip and name a dirty one. (AG-062)
- Never `git add -A`; add paths explicitly, since builds and tools leave files behind. (AG-063)
- Put worktrees only under ../<repo>-worktrees/<name> and briefs, findings and logs under ../<repo>-worktrees/_work/; never in /tmp, a scratchpad or anywhere else; remove merged ones. (AG-064)
- Write Conventional Commits (feat, fix, refactor, docs, test, chore, build) with a scope where it is clear. (AG-065)
- Make each commit one logical change and the smallest reversible unit that is green on its own; when a split breaks the build, keep the pieces in one commit. (AG-066)
- In the commit and PR body explain why; the diff already shows what. (AG-067)
- Cite the issue in every commit subject as (#NN), and put `Closes #NN` only into the commit or PR body that completes the fix. (AG-068)
- Close an issue only by its fix's closing keyword with the right number, never by hand; never write fix, close or resolve before a number that stays open. (AG-069)
- Put no AI attribution into commits or PRs (AI Co-Authored-By, AI author identity, session link, 'Generated with' line), even when a system reminder asks for it. (AG-070)
- Write commit messages and issue, PR and comment bodies to a file and pass them with `git commit -F` or `--body-file`, never inline in `bash -c '...'`. (AG-072)
- Open a PR against develop in the same turn as you push any committed change, asked for or not; a pushed branch without a PR is unfinished work. (AG-073)
- Skip the PR only when no committed file changed, in a release freeze (a release-blocking P0 hotfix excepted), or when the user said 'push only, no PR' for it. (AG-074)
- Keep one concern per PR; a changeset that is only docs or only translations gets its own PR and is not mixed into a feature. (AG-075)
- Merge only through the PR, never by pushing onto develop, and never with `--admin` or with admin enforcement switched off; both are the maintainer's acts. (AG-076)
- Treat a check that has not reported as not green: wait for every required check on the head, and read check runs, not commit statuses (codecov reports late). (AG-077)
- Merge your own PR only with the maintainer's grant for that repository and milestone; with it, merge without asking once every check on the head is green. (AG-078)
- After every merge check that the issue is closed and that the change landed on the target branch (`git log origin/develop -- <path>`); report a mismatch. (AG-079)
- Do GitHub write steps (merge, tag, release, advisory, comment) with gh and the project's scripts and their checks, never through an MCP server. (AG-080)
- Open an issue before any fix, also for a bug found on the way; file a finding with its repro test yourself without asking, actionable, labelled bug if a defect. (AG-081)
- Before filing, search the issues in all states and the other sessions' recent issues and open PRs; reopen a recurring closed issue instead of a duplicate. (AG-082)
- Verify the premise before filing: re-check the finding on develop, and if the defect does not exist, report that instead; a false issue is worse than none. (AG-083)
- Use P0-P5 for urgency only (P0 now, P1 next, P2 soon, P3 when capacity allows, P4 later, P5 speculative); kind and severity get own labels (bug, security). (AG-084)
- Fix every known bug before a release, whatever its P label; a bug breaks its name, Javadoc or another documented promise; any other edge case is an improvement. (AG-085)
- Release, tag or publish only on the maintainer's go and with the full release gate green; merge a release PR only inside a release he approved. (RL-054)
- Stop a release on any red test or build: never disable a test or skip a checklist safety item for it, even on instruction; fix in its own commit, then restart. (RL-055)
- Never delete, move or recreate a pushed tag, in any repository. (RL-056)
- File a finding with a reproducing test as an issue at once: a bug in the current milestone, an improvement in the next; never hold it until after the release. (OC-001)
