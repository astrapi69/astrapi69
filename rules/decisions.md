# Decisions

Read on demand; the rules every session needs are in core/.

- Before a larger architectural change, check the work planned in the area; on a conflict between an instruction and the documented planning stop and ask, and never build a parallel system slated for removal. (AG-107)
- Take a decision that an issue reserves for the maintainer in that issue, in writing, before the code that depends on it; if a commit already took it, make it again visibly in the issue. Before a pull request that implements a decision recorded in an issue is merged, its author, or its reviewer where it has one, checks it against the decision's wording point by point and names every deviation in the merge report; a deviation the author only mentions in the pull request text goes to the maintainer before the merge. A security fix, a change of a persisted format and a rule text are reviewed once before their pull request is opened: on the branch, an agent or a model other than the author reviews it adversarially, with the question and the raw data, not the author's conclusion (AG-005), looking on purpose for counterexamples, unproven assumptions and contradictions; what it finds is a lead and counts only once a test, a measurement or a primary source bears it out. The author fixes the findings in the same session, each with its test, and then opens the pull request: one round, no fix agent and no LLM delta review, the tests prove the fixes; a security or privacy change gets a second round after its fixes. Every other change needs no review: its green checks are its merge. A text only the maintainer reads is exempt (AG-099). (AG-108)
- Leave an issue in the milestone the maintainer put it in. (AG-109)
